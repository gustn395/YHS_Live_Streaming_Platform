| MB-D004 | 비밀번호는 NFC 정규화 뒤 code point 기준 15~64자다. 문자 종류 구성 규칙은 두지 않고, 공백을 허용하며, 자동 Trim하지 않는다. username과 같은 비밀번호는 거부한다. 이메일 OTP는 NIST가 인정하는 다중 요소로 보지 않는다. | NIST SP 800-63B-4 3.1.1.2(비밀번호 단일 인증 시 15자 이상, 구성 규칙 금지, Unicode 정규화 권고), 3.1.3.1(이메일은 out-of-band 인증 수단 불가). | Member 2차 Q6, 3차 Q3, 2026-11-26 |
| MB-D005 (유출 목록 부분 변경 → MB-D010) | 가입·변경 시 비밀번호 전체를 차단 목록과 비교한다. 차단 목록은 실제 유출 비밀번호 목록(NFC 정규화, 15자 이상, 중복 제거)과 문맥 단어(서비스 이름, username과 그 파생어)다. 목록 로딩에 실패하면 검사를 건너뛰지 않고 기동에 실패하며, 비밀번호 원문을 로그에 남기지 않는다. 목록의 원본 URL·커밋 해시·파일명·추출 규칙·라이선스를 기록한다. **공개 저장소에는 개별 데이터의 재배포 권한이 확인된 목록만 넣는다.** 출처 후보는 SecLists(MIT)의 유출 기반 목록이다. | NIST SP 800-63B-4 3.1.1.2(차단 목록 SHALL). 공개 저장소라 데이터 권리를 확인해야 한다. | Member 3차 Q2, R-09, BE-02 ① Q2·2-5 보완, 2026-11-26 |
| MB-D006 | 비밀번호 해시는 NFC → UTF-8 → PBKDF2-HMAC-SHA256(SecureRandom Salt 16바이트 이상, 출력 256비트, 반복 횟수는 설정값·초기 600,000) → HMAC-SHA256(pepper, 출력 256비트)이다. 저장 포맷에 알고리즘·정규화 버전·반복 횟수·키 ID·Salt를 넣고, 검증은 일정 시간 비교로 한다. 중간 PBKDF2 결과는 저장하지 않는다. 반복 횟수가 바뀌면 재해시 대상으로 판정하고, 실제 재해시는 로그인(BE-03) 때 한다. | 명세 M-02, NIST 3.1.1.2(salt·비용 인자·keyed hash 권고). | 명세 M-02, Member 3차 Q3·Q4, R-24, BE-02 ④, 2026-11-26 |
| MB-D007 | 비밀 키(pepper, OTP HMAC 키, JWT 서명 키)는 서로 분리한다. pepper와 OTP HMAC 키는 SecureRandom으로 만든 256비트 키이고, JWT 키의 유형·길이·형식은 서명 알고리즘을 정한 뒤 정한다. 키는 기본값 없는 환경변수로만 받고 Git·로그에 노출하지 않으며, 테스트는 테스트 전용 키를 쓴다. 이미 도입한 기능의 키만 필수이고, 키 누락·형식 오류·키 ID 누락이면 기동에 실패한다(오류 메시지에 키 값 금지). 키를 도입하는 작업마다 기동 실패 테스트를 둔다. | 키 하나가 유출돼도 다른 용도의 키가 안전하도록 분리하고, 잘못된 키로 해시가 저장되는 일을 막는다. | Member 3차 Q4, 5차 Q1, R-07·R-08·R-19·R-20, BE-02 2-5 보완, 2026-11-26 |
| MB-D008 | username은 4~20자 `[a-z0-9_]`이고 소문자로 정규화한다. 이메일은 앞뒤 공백을 제거하고 소문자로 정규화한다. 닉네임은 2~20자이고 앞뒤 공백을 제거하며 제어 문자를 금지하고 중복을 허용한다. username·이메일 중복은 409와 각각의 `code`로 응답하고, 동시 가입은 DB UNIQUE 제약으로 막는다. | 대소문자만 다른 중복 계정을 막고, 동시 요청에서도 중복 저장이 생기지 않게 한다. | Member 2차 Q7, BE-02 2-5 보완, 2026-11-26 |
| MB-D009 | 회원가입에서는 username·이메일 중복을 안내한다. 로그인·OTP 등에서는 계정 존재 여부를 노출하지 않는다. | 가입 화면의 사용성과 열거 방지(명세 5장)의 범위를 나눈다. | Member 2차 Q7, 2026-11-26 |
| MB-D010 | 유출 비밀번호 검사는 HIBP Pwned Passwords range API(k-익명성)로 한다. 비밀번호를 NFC → UTF-8 → SHA-1로 바꿔 앞 5자만 보내고(`Add-Padding: true`), 받은 접미사 중 건수 0(패딩)은 무시하며, 건수 1 이상이면 거부한다. 거부는 서비스 계층에서 400 `MEMBER_PASSWORD_BREACHED`(고정 문구, `errors[]` 없음)로 응답하고 해시·저장을 하지 않는다. 시간 초과(연결 1s·읽기 2s), 200 이외 응답, 빈 응답, 형식 오류는 모두 확인 불가로 보고 503 `MEMBER_PASSWORD_CHECK_UNAVAILABLE`로 가입을 거부한다(fail-closed, 비정상 응답을 통과로 보지 않음). 재시도·응답 캐시는 두지 않는다. 비밀번호 원문·전체 SHA-1·앞 5자·그 값이 든 URL은 로그·예외 메시지에 남기지 않는다(HTTP 클라이언트 예외 메시지·스택 포함). 호출과 PBKDF2 해시는 DB 쓰기 트랜잭션 밖에서 한다. 로컬 유출 목록(파일·로더·기동 실패 규칙)은 두지 않는다. MB-D005 중 문맥 단어 검사, 비밀번호 전체 비교, NFC, 원문 로그 금지, 공개 저장소에는 권리가 확인된 데이터만 넣는 원칙은 유지한다. 테스트는 실제 HIBP를 부르지 않고 스텁·대역을 쓴다. | NIST SP 800-63B-4 3.1.1.2(차단 목록 SHALL). 로컬 후보(SecLists xato-net·Probable-Wordlists)는 재배포 권한을 확인하지 못했다. HIBP API는 키·라이선스·출처 표기 요구가 없고(API v3 문서) 원문·전체 해시를 보내지 않는다. 장애 시 가입 중단을 감수하고 유출 비밀번호 통과를 막는다. | BE-02 HIBP 라운드 Q1=b·Q2=a·Q3=b·Q4=a와 보완 조건, 2026-11-26 |
