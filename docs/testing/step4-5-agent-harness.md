## 1. 결정

| ID | 결정 | 이유 |
| --- | --- | --- |
| Q1 | 커밋 범위: `AGENTS.md`·`CLAUDE.md`·`docs/` 문서는 커밋, `CLAUDE.local.md`·`.claude/`는 로컬 | 공통 규칙은 공개·CodeRabbit 기준으로 쓰고, 개인 Hook·승인 기록은 공개하지 않는다 |
| Q2 | Workflow Skill은 프로젝트 로컬 `yhs-feature-workflow`·`yhs-grill-with-docs` | 다른 저장소용 전역 Skill과 이름·규칙이 섞이지 않게 한다 |
| Q3 | 구현 시작 승인은 사용자 입력 명령으로만 기록하고 Hook이 구현 경로 쓰기를 검사 | 에이전트가 승인을 스스로 만들 수 없게 한다 |
| Q4 | 출력 간결화 Skill(Caveman)은 공식 저장소의 고정 커밋 `SKILL.md`만 로컬 복사, 수동 호출 | Hook·telemetry·외부 전송 없이 쓰고 다른 프로젝트에 영향을 주지 않는다 |
| Q5 | 문서·결정 ID는 모듈 접두 ID(`<P>-D###` 등), 기존 Step 결정 번호는 그대로 두고 링크 | 모듈별로 독립적이고 번호가 충돌하지 않는다 ([INDEX 3장](../INDEX.md#3-id-체계)) |
| Q6 | 자체 리뷰 단계에서 이해도 퀴즈 필수, 보안 변경 시 보안 리뷰 조건부 필수 | 학습 목표와 인증 도입 단계의 보안 점검 |
| Q7 | 브랜치 `feature/<Issue 번호>-<module 또는 영역>-<요지>`, Issue 번호를 받은 뒤 바로 생성 | Issue와 브랜치를 바로 연결한다 |
| Q8 | Bot 리뷰 도착은 사용자가 붙여 넣은 CodeRabbit 리뷰 내용으로 감지해 기록 | PR URL 없이 리뷰만 붙여 넣는 사용 방식에 맞춘다 |
| Q9 | 보안 변경 감지가 오탐이면 사용자가 그 사이클만 면제(이유 기록) | 오탐 비용을 줄이면서 면제 이력을 남긴다 |
| Q10 | 업무 규칙 원본: `docs/policy.md`는 현재 유효한 규칙, 모듈 `decisions.md`는 결정 이력·이유·미결, 공통 결정·미결은 `policy.md` 3·4장 | 현재 규칙과 이력을 나눠 원문을 한 곳에 둔다 |
| Q11 | 7개 모듈에 문서 7종과 모듈 `AGENTS.md`를 미리 만든다(신규 62개: 공통 6 + 모듈 문서 49 + 모듈 AGENTS 7) | 모든 모듈이 같은 구조로 시작하게 한다 |
| Q12 | 하네스 문서는 한 PR로 낸다 | 같은 구조의 문서라 리뷰 부담이 크지 않다 |
| Q13 | `backend/README.md` 8장 미결 2건을 새 원본으로 이관(인증 방식 → `docs/member/decisions.md`, DB 연동 테스트 방식 → `docs/policy.md`), README에는 링크만 | 미결 원문을 한 곳에 둔다. 확정하지 않고 미결 상태·원문·근거를 보존한다 |
| Q14 | 구현 승인 범위 `X/**`는 `X` 디렉터리 자체를 포함한다(유사 경로·`..`·링크 이탈 제외, 보호 경로 우선, 재귀 삭제는 따로 확인) | 패키지 디렉터리 생성·삭제를 범위 안에서 할 수 있게 한다 |
| Q15 | 승인 뒤 구현 계획이 바뀌면 그 승인은 영구 무효(원복해도 다시 살아나지 않음) | 계획 변경 이력을 숨길 수 없게 한다 |
| Q16 | 출력 간결화는 호출 인자로 지정한 보고에만 적용하고 끝나면 일반 문체로 돌아간다. 정책 질문·학습 설명·승인 요청에는 적용하지 않는다 | 정확성과 이해도를 우선한다 |

Q2~Q4, Q6, Q8, Q9, Q14~Q16은 개인 하네스(Git 제외, 저장소 밖)에 관한 결정이라 저장소 파일로는 확인할 수 없다. 이 PR에서 저장소에
반영되어 저장소 파일로 확인할 수 있는 결정은 Q5, Q7, Q10, Q11, Q13이다. Q1은 커밋 범위 부분만 확인할 수 있고(로컬 제외는 각
PC의 `.git/info/exclude`), Q12는 PR에서 확인한다.
